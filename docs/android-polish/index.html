🚨 1. Android Crash Root-Cause Audit

The user reported that the Android build currently crashes frequently. We inspected the entire Android native and WebView pipeline and identified 5 concrete crash vectors:

CRASH VECTOR 1

ForegroundServiceStartNotAllowedException & RemoteServiceException

Trigger: MainActivity.onCreate() initiates ContextCompat.startForegroundService(this, serviceIntent) immediately on cold launch.

Why it crashes: On Android 12 through Android 14 (API 31–34), starting a media foreground service while the app is booting or before active playback begins is blocked by the OS. If notification binding fails to complete within 5s, Android terminates the host process with a fatal RemoteServiceException.

Fix: Deferred service activation: MediaPlaybackService is only started when the user actually initiates playback (first play event).

CRASH VECTOR 2

Chromium RenderProcessGone Unhandled Fatal Termination

Trigger: Missing WebViewClient.onRenderProcessGone() handler in MainActivity.kt.

Why it crashes: If Android's GPU or renderer runs out of memory or hits an internal compositor glitch, the default Android OS behavior is to immediately kill the application process with SIGKILL.

Fix: Implement onRenderProcessGone in a custom WebViewClient returning true, cleanly handling recovery rather than letting the system kill the app.

CRASH VECTOR 3

Dangerous Background Reflection Loop on WebView

Trigger: MainActivity.kt runs a 1500ms Handler calling private reflection View.onWindowVisibilityChanged(View.VISIBLE) while in background.

Why it crashes: Forcing a detached or background WebView surface to report VISIBLE causes internal Chromium C++ assertions and SIGSEGV in libmonochrome.so on modern Android builds.

Fix: Eliminate the reflection loop. Background audio is safely kept alive through mediaPlaybackRequiresUserGesture = false and native PARTIAL_WAKE_LOCK / WifiLock.

CRASH VECTOR 4

GPU Texture Allocation Failure from Full-Screen 60px CSS Blur

Trigger: OverlayPlayer.tsx full-viewport dynamic blur-[60px] background image.

Why it crashes: On mobile GPU chips (Mali / Adreno), applying an unclipped 60px blur over a 1080x2400 viewport allocates enormous framebuffers, rapidly exhausting GPU RAM and triggering renderer termination.

Fix: Replace full-screen image blur with lightweight CSS ambient gradients and pre-scaled 32x32 color-sampled canvas backdrop.
